### 핵심 발견
1. **이중 코드 경로 분기** — MainWindow는 EffectManager+EffectConverter, BattleSimulator/EquipmentOptimizer는 BuffCalculator(레거시)를 사용. 같은 의미를 두 구현으로 분기 중.
2. **EffectManager vs BuffCalculator 의미 차이 (잠재 버그)** — 턴제 버프 집계 시 BuffCalculator는 Conditional∪Active를 한 카테고리로 MaxMerge하지만, EffectManager는 4개 하위 카테고리로 쪼개 카테고리 간 Add. 결과가 달라질 수 있음.
3. **Models→DB 역방향 의존** — Models/Equipment.cs가 EquipmentDb·SubOptionDb 정적 호출, Models/Formation.cs가 StatTable.FormationDb 호출. SubOptionDb는 Models/Equipment.cs 안에 정의되어 있음.
4. **네임스페이스 불일치** — DB/StatusEffect.cs만 `GameDamageCalculator.Models` 네임스페이스, 나머지 DB 파일은 `GameDamageCalculator.Database`.
5. **Skill/Passive fallback getter 비대화** — StatusEffects, CoopAttack, MarkAttack, PainEndurance, FlatBonus, StatScalings 모두 "레거시 set 우선 → null이면 Effects 리스트 검색" 패턴. 캐릭터별 마이그레이션 진척이 달라 현재 필수지만 마이그레이션 종료 시점 명시 필요.
6. **PersistentEffect 특수 메카닉 부분 통합** — EffectConverter.FromPersistentEffects가 CoopAttack/MarkAttack/StatScaling/PainEndurance/FlatBonus를 BattleEffect로 변환하지 않고 `continue`. "통합" 명칭과 달리 일부 메카닉은 별도 경로 유지.
7. **MainWindow.xaml.cs 거대화** — 2071 LOC, 62 메서드. 비즈니스 로직이 코드비하인드에 몰려 있음.
8. **웹 포팅 관점** — DamageCalculator는 입력→결과 순수 함수에 가까워 TS 포팅 용이. StatCalculator/EffectConverter/Models가 정적 Db 클래스를 직접 호출하는 부분이 가장 큰 포팅 장애물.

## Q: 검수 후 정리 작업

### 게임 룰 확정 (사용자 진술)
- **상시·턴제·펫 3카테고리, 카테고리 내 MaxMerge·간 Add** (β 해석 확정).
- "같은 종류"는 BuffSet 필드 단위. 여포 「용이무모」 = Atk_Rate 같은 필드 → 아일린과 MaxMerge. 에스파다 「마력 정화」 = Mark_Purify 별도 필드 → 키리엘과 Add.

### 트루드 「전투의 희열」 PainEndurance 룰
- 직접 피해가 최대 HP의 10% 이상 시 발동.
- 25% 즉시 받음. 75%는 5턴에 걸쳐 매 턴 15%씩 분산.
- 발동 누적 가능 (각각 독립 큐).
- 분산 처리 시점: 트리거된 그 평타 직후가 아니라 **다음 본인 평타 차례 시작 시 1회 처리 후 평타**.

### 추가 룰 (다음 라운드 적용 대상)
- 모든 턴제 디/버프와 상태이상의 턴 차감은 **이펙트 보유자(=시전자)가 평타할 때 발생**.
  - 상태이상: 평타 **전** 적용 + 턴 차감.
  - 디/버프: 평타 **후** 턴 차감.

### 플랫폼 결정
- WPF exe 빌드 중단. 웹(Next.js + TS, Vercel) 서비스로 이전.
- WPF UI 리팩토링 가치 낮음. 핵심 로직(Services/, Models/, DB/)만 정합성 확보.

### 코드 변경 (이번 세션 누적)

**검수 정리분**:
1. `EffectManager` 집계 의미 수정 — 카테고리별 MaxMerge 후 Add였던 것을 카테고리 묶음 통합 MaxMerge로 변경. `GetSeparatedBuffs` / `GetTotalDebuffs` / `AggregateBuffsByCategories` 수정.
2. `BuffCalculator` 완전 제거. `BattleSimulator`, `EquipmentOptimizer`, `MainWindow`에서 `EffectManager` 경로로 이전. -233 LOC.
3. `DB/StatusEffect.cs` 네임스페이스 → `GameDamageCalculator.Database`. enum은 `Models/StatusEffectType.cs`로 분리.
4. `SubOptionDb`를 `Models/Equipment.cs` 안에서 `DB/SubOptionDb.cs`로 분리.
5. `StatCalculator`에 `FlatBonus` 합산 추가 — 밀리아 「광채의 수정비늘」 (Def +1009, Hp +3929) 정상 적용.
6. `PersistentEffectType` enum에 두 그룹(BattleEffect 변환 / 별도 채널) 표기 코멘트.
7. `EffectConverter`의 `continue` 분기에 의도 + 소비 위치 명시 코멘트.

**PainEndurance 인프라 + 시뮬 흐름**:
8. `BattleState.cs`: `PendingPainEnduranceDamage` 클래스 + `CharacterBattleState.PainEnduranceQueue` 필드.
9. `BattleSimulator.cs`: `ApplyIncomingDamage` / `TickPainEnduranceQueue` / `GetActivePainEndurance` / `CalculateIncomingDamage` / `ResolveEnemySkill` 헬퍼 추가.
10. `ExecuteEnemySkill` — 광역 받피해 적용 (DamageCalculator를 attacker=보스/target=아군 의미로 호출).
11. `ExecuteAllyNormalAttack` 시작 부분에 `TickPainEnduranceQueue(charState)` — 룰 (트리거 후 다음 본인 평타에 분산 1회 처리) 적용.
