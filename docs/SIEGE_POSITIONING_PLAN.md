# 공성전 자리배치(전/후열) 빔 아티팩트 — 다음 작업 계획

## 배경 (2026-06-05 조사 결과)

목요일(라이언·타카·레이첼·비스킷·돼오, 6초월·잠재0) 자동 최적이 **라이언(38.5% 딜러)을 전열**,
**레이첼(8.5%)을 후열**에 두는 의문 발생. 강제 비교 결과:

| 자리 (밸런스 진형) | 총점 | 라이언 | 타카 |
|---|---|---|---|
| 후열 타카,레이첼 (옵티마이저 선택) | 12,893,630 | 4.96M | 6.29M |
| 후열 타카,라이언 (강제) | 12,782,372 | 5.83M(↑) | **4.90M(↓1.39M)** |

- 후열 공격%는 **per-char 고정**(밸런스 = 각 21%, `Atk_Rate_Back=21 × BackRowCount=2 = 42`).
  따라서 라이언-후열은 라이언에게 +21% **순증가**여야 하고 타카는 양쪽 동일(21%)해야 함.
- 그런데 타카가 6.29M→4.90M로 급락 = **빔이 타카 시전을 줄이고 부스트된 라이언 시전을 늘림**.
- **논리적 진짜 최적**: 타카를 6.29M로 유지 + 라이언만 부스트(4.96→5.83M) → **~13.4M** (현재 12.89M 초과).
  빔이 "라이언이 세졌으니 더 쓰자"는 탐욕적 분기로 빠져 타카를 희생한 **지역최적(12.78M)에 갇힘**.
- ∴ **라이언 전열은 빔서치 아티팩트**. 자리는 빔이 각 config마다 다른 지역최적을 찾아 비교가 불공정한
  2단계 자리탐색 한계(기존 known issue). 유저 직관(라이언 후열)이 옳음.

관련 수정(오늘 커밋): `3d86c4e` 스킬 자기 시전시간 자기 쿨감 버그(광풍참 4→3회).

## 다음 작업

### 1. 라이언-후열 검증 (목요일) — ✅ 완료 (2026-06-05). **결론: 라이언-후열이 옳음 (doc 원래 가설 확정).**

3번의 반전 끝에 확정. 핵심 원인은 시뮬의 **강자사냥 도발+물리면역 미모델**이었다. (`tools/SiegeRyanBackExp`)

**(1) 초기 실험 (메커니즘 전) — 잘못된 "전열" 결론:** 라이언-후열 빔 12.78M < 전열 12.89M → "스킬턴 경쟁으로
후열 손해"로 판단 → **틀림**. 원인: 시뮬이 강자사냥 효과를 안 돌려 라이언이 랜덤 타겟팅으로 죽고, 델론즈
「죽음의 경계」(아군 사망 시 보스 피해무효[4회])가 터져 점수가 깎였다. (당시 빔이 doc의 12.78M을 재현해 결론을
오확신했음.)

**(2) 빠진 메커니즘 발견·구현:** 델론즈 죽음의 일격 = **단일 물리**(TargetCount=1, 300%×5, OnKillRecast).
강자사냥(강화) = **자신 도발[2턴] + 물리 피해 면역[2턴]**. → 도발로 델론즈를 라이언에게 유도 + 물리면역으로
0뎀 → 사망 0 → 죽음의 경계 미발동. 공성 시뮬에 이 둘이 없어서(메인 시뮬엔 있음) 추가:
  - 도발 타겟팅(`PickRandomAlly/Allies`), 타입별 피해무효(`ApplyDamageToAlly` — 메인 시뮬 패턴 이식),
    적 공격 타입(`Enemy.AttackType`, 기본 물리), 강자사냥 시전 시 도발/면역 상태 적용(`HandleEffects`).
  - (라이언 평타쿨감·델론즈 1→2스킬 우선순위·초기반 쿨은 이미 모델링돼 있었음 — 빠진 건 도발/면역 둘뿐.)

**(3) 공정 비교 (메커니즘 후, 같은 로테·자리만 교체):**
| 로테이션 | 후열 자리 | 전열 자리 |
|---|---|---|
| 전열 우승로테 | **13,576,296** | 13,384,139 |
| 후열 우승로테 | 12,365,000 | 12,205,813 |

→ **같은 스킬순서면 후열 자리가 항상 높음(전원 생존 5/5).** 후열 +21% 공격%가 스킬턴 경쟁 손해보다 큼 =
  **doc 원래 가설이 맞았다.** 후열 천장 13.58M > 전열 천장 13.38M.

**(4) 빔 저평가 교정:** 후열 자체 빔은 12.37M 지역최적에 갇혔다(전열 우승로테@후열=13.58M가 더 높음).
`SiegeOptimizer`에 **교차수분**(빔 후보들의 우승 로테를 서로의 config에 교차평가, 무회귀) 추가 → 옵티마이저가
후열의 더 높은 로테를 채택하게 됨.

**(5) 프로덕션:** 목요일 배치 = **밸런스 / 후열 라이언·타카 / 12,993,127** (라이언-후열 채택 ✓).
  단 생존반지가 교차수분 *이후* 적용돼 천장(13.58M)보다 ~0.58M 낮음 → **반지-순서 정렬은 후속 개선 여지.**

### 2. 메인딜러-후열 휴리스틱 상위 2딜러 확장 — ✅ 완료 (2026-06-05, `SiegeOptimizer.cs`)
- 현재 `SiegeOptimizer`의 `bestDealerBack`은 **1위 딜러만 후열**인 config를 빔 후보로 추가.
- 타카(1위)는 이미 후열이라 라이언(2위)-후열 config가 빔평가에서 누락됨.
- **확장**: 후열 인원수만큼 **상위 N딜러 전원 후열** config를 빔 후보에 포함
  (밸런스 2명 → 상위 2딜러 = 타카+라이언 후열도 빔평가). 이로써 라이언-후열이 공정 비교됨.

**구현 (B2):** (조합×진형) 그룹의 전 마스크 결과를 모아, **그룹 내 캐릭별 '최대' 데미지**로 딜러를 가린 뒤
(전열 등 최선 배치에서 찍은 값 → 후열에서 자동로테가 과소평가해도 딜러로 식별됨) 그 상위 `requiredBack`명이
전원 후열인 config를 진형별로 빔 후보에 추가. 첫 시도는 딜러 식별을 config별 자동로테 데미지로 해서
**실패**(자기모순 — 자동로테가 후열딜러를 과소평가 → 정작 그 config에서 빠짐)했고, 그룹 최대로 교체해 해결.

**검증 결과 (목요일, 쿨감수정 `3d86c4e` 반영, 빔폭10·깊이28):** 라이언-후열이 이제 정상 빔평가됨.
| 진형·후열 | 자동로테 | 빔 |
|---|---|---|
| 밸런스 / 타카·레이첼 (라이언 **전열**) | 5,105,440 | **12,553,787** ← 채택 |
| 밸런스 / 라이언·타카 (라이언 **후열**) | 3,383,114 | 12,508,645 |
| 기본 / 라이언·타카·레이첼 | 2,908,504 | 12,522,074 |

→ (당시) 라이언-후열(12.51M) < 라이언-전열(12.55M), 차이 45K(0.36%).

> ⚠️ **(정정)** 위 "전열 0.36% 우위"는 **강자사냥 도발+물리면역 미모델 상태**의 수치다. 작업 1에서 그 둘을
> 구현한 뒤 공정 비교(같은 로테·자리만 교체)에서 **라이언-후열이 옳음**으로 확정됐다(후열 13.58M > 전열 13.38M).
> 위 표·수치는 과정 기록용. 작업 2의 (B2) 휴리스틱(상위 N딜러 전원후열 빔후보화) 자체는 유효하며, 작업 1의
> 교차수분과 함께 옵티마이저가 라이언-후열을 선택하게 한다.
